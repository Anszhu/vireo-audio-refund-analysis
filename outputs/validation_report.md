## 40-Case AI Secondary Review

**Reviewer: Claude AI assistant.** This is supplemental secondary-review evidence, not independent human validation. The same assistant contributed to rule development, so agreement may be optimistic. Independent human validation was not completed during the assignment window. Reviewer type is recorded as `ai_assistant` in `review_summary.csv`.

**Population this applies to.** 40 refund tickets, drawn by seeded stratified sampling from the 2,340 canonical refund tickets: 10 the rules called confirmed, 10 likely, 8 ambiguous, 12 refund tickets the rules did not flag. The strata over-represent flagged cases, so **these figures describe this sample only and must not be generalised to the whole dataset**. Tickets already used in the AI-labelled samples of section C were excluded.

**Methodology and reviewer process.**
1. For each ticket the reviewer read: structured fields (refund amount, reason code, `replacement_issued`, order id and how it was matched, status, team/tier), the product, the customer message and agent note (customer and agent names redacted), every other ticket on the same order, and policy §5-§6.
2. The **existing class was hidden while labelling** (last column of the sheet, not opened until every label was recorded); the comparison was done afterwards, by code. Labels were not optimised for agreement.
3. Definitions: *confirmed* = structured data and/or several sources clearly establish refund and replacement for the same order; *likely* = strong evidence, one piece missing; *ambiguous* = points to a possible issue but cannot establish it; *not_confirmed* = evidence does not establish it. A request, an offer, "raised" or "approved" is **not** treated as a replacement issued; a keyword alone never upgrades a case.
4. Limits of the blindness: the reviewer knew the sample was stratified and had helped write the rules, and no dispatch or fulfilment data exists, so no case can be verified beyond the agent's own records.

**Disagreement types:** existing *ambiguous* → reviewer *not_confirmed* (3). In each, the refund's own text describes an order that was never fulfilled (cancellation or a payment reversal) or a separate incident, so the reviewer judged the cross-ticket signal insufficient. None involved a keyword false positive, a duplicate-ticket effect or a requested-vs-issued confusion; the requested/offered/declined cases were handled correctly.

**Other observations from the review (not part of the classification).** In 6 of the 40 reviewed tickets another ticket on the same order carries a refund of the **same amount** (a possible duplicate refund; 6 is a count in this stratified sample, not a rate). This is outside the refund + replacement question and was not analysed further. Several reviewed refund-plus-replacement tickets were handled by Tier 1 agents although policy §6 reserves warranty replacements to Tier 2.

**Conclusions.**
* **No production rule or count change is warranted.** There were 0 false positives and 0 false negatives (confirmed/likely vs the rest), and all 3 disagreements are inside the non-financial *ambiguous* class, so the counts behind the money figures (165 confirmed / 179 likely / 197 ambiguous) are supported by this sample and are **not** changed.
* A rule refinement (do not flag cross-ticket cases when the refund is a cancellation or payment reversal) was considered and **not applied**: it would affect up to 51 of the 173 cross-ticket flags by reason code, but in this sample the reviewer's split was not separable by reason code (one CANCEL case was kept ambiguous), the sample has only 3 disagreements, and it would only shrink the ambiguous count, not any money figure.
* The 12 unflagged tickets showed no missed cases, which bounds the miss rate only loosely (rule of three: at most about 25% at 95%). No claim is made about the unflagged population.
* Agreement is expected to be optimistic because the reviewer is not independent. Independent human validation remains **pending**.

## Limitations - what was NOT validated
* No independent human review by a person has been completed (section D is an AI-assistant review). No external ground truth exists for the "true refund reason".
* Agents' reason-code accuracy was **not** measured against a gold standard; the classifier only shows text/code disagreement.
* Rule topic vs recorded non-GW-OTHER codes: CANCEL, DUP-PAYMENT, LOST-TRANSIT, PRICE-ADJ agree well where the text is informative; DOA-REPL, WTY-BUYBACK and RETURN-QC-OK overlap heavily in wording, so mismatches there are **review prompts, not errors**.
* The fallback order join (customer_id + SKU) was not verified ticket by ticket (3,804 tickets). 53 of the 173 cross-ticket "ambiguous" flags rest on such an inferred order; they never feed the financial figures.
* The rules were tuned on the development sample and partly on the hold-out; there is no untouched third sample.
